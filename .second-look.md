# Review guidelines for this repository

Second Look reads this file from the main branch and passes it to the reviewer
as team rules. Edit it to match how your team works.

## Application code (TypeScript)

- Database access goes through `src/db/queries.ts`. Flag SQL written anywhere else.
- Never log tokens, diffs, file contents, or model output.
- All input from outside the app (HTTP bodies, webhooks, model output) must be validated with Zod.
- New logic needs a test that can fail.

## Platform invariants (the C# sample under `demo/`)

These are examples of rules a multi-tenant business platform would write down.

- Tenancy: every query on a tenant-owned table filters by the current tenant. `IgnoreQueryFilters()` is not allowed outside admin tooling.
- Access control: every controller action that changes data has an `[Authorize]` policy.
- Migrations: a migration must keep the data in existing rows. Use `RenameColumn` for renames. A new required column needs a backfill before the constraint is added. Say in the PR description what happens to existing rows.
- Auditing: changes to work orders and customers record who made them and when.
